## 2. Hermes Wiring

### 2.1 Provider Configuration Fix

**Problem:** Hermes was pointing at Ollama (port 11434) instead of llama-server (port 8080).

**Root cause:** `model.provider: ollama-launch` took precedence over `model.base_url`. The provider's `api` field (11434) overrode the base_url (8080).

**Fix:** Added `llama-server` provider block in config.yaml:
```yaml
providers:
    llama-server:
        api: http://127.0.0.1:8080/v1
        default_model: LiquidAI/LFM2.5-8B-A1B-GGUF:Q4_0
        models:
            - LiquidAI/LFM2.5-8B-A1B-GGUF:Q4_0
        name: llama.cpp
```
Changed `model.provider: ollama-launch` → `model.provider: llama-server`.

**Lesson:** In Hermes, `provider` name must match a key in `providers:`. The `base_url` alone is not sufficient — the provider lookup wins.

### 2.2 Config Caching

**Discovery:** Hermes reads config at startup and caches it. Changes to `config.yaml` require restarting the `hermes` process.

**Evidence:** After editing config.yaml, Hermes still used old settings until killed and relaunched.

**Operational impact:** Every config change requires `Ctrl+C` → relaunch `hermes --provider llama-server`.

### 2.3 CLI Provider Override

**Discovery:** `hermes --provider llama-server` forces the provider regardless of cached state.

**Use case:** When config changes aren't picked up, or when testing different providers.

### 3.2 Tool Accuracy Issue

**Symptom:** When asked "list .md files in my project folder", Hermes:
1. Tried `browser_navigate` (DNS error — tried to go online)
2. Searched wrong directory (`~/hermes-agent/` instead of project)
3. Eventually found `~/Hermes_Learning/` but listed home directory contents

**Root cause:** LFM2.5-8B-A1B is a 7B MoE with ~1B active parameters. Precise multi-step tool use (parse path → construct command → execute → interpret output) is at the edge of its capability.

**Workaround:** Give explicit paths in conversation, not just in AGENTS.md. The model needs direct instruction, not project-level context.

### 3.3 Browser Tool Firing

**Symptom:** When local file search fails, Hermes tries `browser_navigate` to go online.

**Root cause:** `toolsets: [hermes-cli, web]` in config.yaml enables browser tools. When local search returns empty, model defaults to web search.

**Fix options:**
1. Remove `web` from toolsets (disable browser entirely)
2. Accept it as a fallback behavior (costs ~2s per failed attempt)
3. Add `web_search` to toolsets (requires API key)

**Decision:** Skip web search for now. Remove `web` from toolsets if it becomes annoying.

## 5. Testing Methodology (Learned Today)

### 5.1 Layer Separation

| Layer | Question | Tool | Test method |
|---|---|---|---|
| Resource | Does it fit? | nvidia-smi, formula | VRAM/RAM check |
| Transport | Does server serve what flags claim? | /props, empirical probe | Send >claimed tokens |
| Quality | Does it reason correctly? | Known-answer probes | ARITH, SPELL, CONTROL |
| Compatibility | Does it speak client's dialect? | Integration probes | tools param, <action> format |

### 5.2 Key Principles

1. **Never trust flags — trust observations.** Config is intent; response is the contract.
2. **Repeat to separate fluke from fact.** Run 3-4×. All-wrong = systematic.
3. **Audit your instrument first.** `max_tokens=80` starved CoT → false negative. Harness bug masquerading as model failure.
4. **Capacity ≠ quality.** Transport pass (served) ≠ retrieval pass (used). Measure both.
5. **Design controls.** SPELL vs CONTROL isolates tokenizer vs intelligence. One variable at a time.
